# README Strategy

The repository benefits from intermediate README files. The root README is good for a first impression, but it cannot explain the value of each course or assignment without becoming too long.

## Recommended Structure

Use three levels:

1. Root README: portfolio overview, strongest highlights, repository map.
2. Semester README files: short orientation pages that explain the role of each semester in the MSc progression.
3. Course README files: the main evidence layer, with assignment-by-assignment tables explaining what was built, analyzed, and learned.

Assignment-level README files should be reserved for larger self-contained projects, such as SAT solving, explainable AI projects, deep reinforcement learning projects, and the air-quality prediction application. Adding one README to every small exercise would create too much noise.

## What A Course README Should Contain

Each course README should answer:

- What technical area does this course cover?
- What did each assignment involve?
- Which skills does the assignment demonstrate?
- Which artifacts should a visitor inspect first?

The best format is a compact table:

| Assignment | What it covers | Skills demonstrated | Main artifacts |
| --- | --- | --- | --- |

This makes the repository much less generic because a visitor can connect each folder to concrete skills.

## Current Implementation

This second iteration adds semester and course README files for the main academic structure. They are intentionally concise, but specific enough to communicate the contents of each assignment without forcing the reader to open every notebook first.
